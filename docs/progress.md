## 주제 전환 (2026-11-04)

- Road Sensor(여러 차의 와이퍼·라이트·브레이크를 모아 앞길 알림)에서 Fuel Mate로 바꿨다. 이유: 도로 데이터가 앱이 깔린 차에서만 나와 출시 초기에 비어 있고, 공공데이터로 채우면 내비와 겹친다
- 확인 결과와 결정: [pivot-fuel.md](pivot-fuel.md). MVP는 주유·충전소 추천 중심 + 운전 습관 비용 한 줄, 내연기관·전기차 모두 지원하고 시연은 휘발유(2026-11-04에 전기차에서 바꿈, [pivot-fuel.md](pivot-fuel.md) 12장)
- 이전 코드는 로컬 태그 `archive/road-sensor`(커밋 `780d23a`)에 있다. 그때 확인한 Pleos SDK 사실(Vehicle·NaviHelper·주행 규제·Gleo 연동·핸들 각도)은 `docs/pleos/`에 남겼다
- 저장소를 비우고 다시 시작(사용자 결정): 서버·시뮬레이터·지도 렌더러·기상청 연동·시험 앱을 지웠다. 수집 서비스, 차량 어댑터(브레이크·속도·기어·주행 규제), 위치 공급원(NaviHelper·데모 궤적), 급정거 판정, 거리계는 패키지 `io.fuelmate`로 옮겨 남겼다
- 저장소 밖 백업(git에 없던 파일): `~/Developer/road-sensor-backup-20261104/`(기상청 키 `.env`, 이전 기획서 docx, Gleo·핸들 시험 앱)

## 에너지 어댑터 (2026-11-04)

- 구조: 공급원(`app/.../energy/`) → `Action.EnergyReading`(종류·출처·잔량·용량·퍼센트) → `:core` 리듀서가 `AppState.energy`와 계량기(`energyMeter`: 이번 실행에서 쓴 양·넣은 양)를 고친다. 양은 연료 L, 전기 kWh. 원화 환산은 단가 단계에서 붙인다
- 공급원 3가지(`EnergyMode`, 실행 인텐트 `--es energy ...`로 바꾸고 저장)
  - `VEHICLE`: AAOS `INFO_FUEL_TYPE`으로 종류를 고르고, 전기는 Pleos `EvBattery`(잔량 Wh·SoC·용량), 연료는 Pleos `Fuel.getFuelPercent` × 탱크 용량(AAOS `INFO_FUEL_CAPACITY`, 못 읽으면 55L 가정). 종류를 모르면 연료차로 본다
  - `DEMO_EV`: 77.4kWh 전기 SUV 가정값, 35%에서 시작. 1초마다 속도·기어로 소비 계산(가속·구름저항·공기저항, 회생 60%, 보조 0.6kW)
  - `DEMO_FUEL`(기본, 2026-11-04에 바꿈): 2.5L 휘발유 세단 가정값(효율 25%, 공회전 0.8L/h), 60L 탱크 25%에서 시작
  - 정속 100km/h 소비: 데모 전기 약 18kWh/100km, 데모 연료 약 7L/100km(테스트로 범위 확인). 데모 소비는 우리 가정값이라 시연용이고 추정 검증에는 못 쓴다
- 계량기 규칙: 줄면 쓴 양, 한 번에 용량 5% 넘게 줄면 값 조정(Virtual Console)으로 보고 안 셈, 달리면서 늘면 회생(쓴 양에서 뺌), 서서 늘면 주유·충전
- 에뮬레이터 확인: 세 모드 모두 화면에 잔량이 나온다. `VEHICLE`은 Pleos 값(SoC 47%, 12.0/77.4kWh: 예전 시험 때 Virtual Console로 바꿔 둔 값)
- Virtual Console 주행 확인(데모 전기차, `adb logcat -s FuelMate`의 "데모 에너지" 줄): P단 정지 0, D단 정지는 보조 전력만큼 조금, 0 → 111km/h 약 6초에 0.246kWh, 113 → 0 감속에서 0.164kWh를 되찾아 한 번 가속·정지에 순 0.118kWh. 충전은 0 그대로
- 고친 것: 처음에는 "지금 속도"로 회생·충전을 갈라서 멈추는 순간 되찾은 양이 충전으로 세졌다(잔량이 속도보다 늦게 온다). 마지막으로 움직인 지 10초 안에 늘면 회생으로 본다(`EnergyRules.REGEN_WINDOW_MS`)
- 알아 둘 것: 에뮬레이터는 최대 약 5.6m/s²로 가속해서 고속에서는 바퀴 출력이 300kW를 넘는다. 처음에는 데모 모델이 160kW에서 잘라 소비를 적게 셌고, 습관 비용이 운행 소비보다 커지는 모순이 나서 상한을 500kW로 올렸다(습관 비용 단계)
- 새로 안 것: Pleos `getEvBatteryCapacity`는 `pleos.car.permission.CAR_ENERGY`만으로는 `SecurityException`이 난다. `pleos.car.permission.CAR_INFO`(normal)를 함께 선언해야 한다
- 아직 안 한 것: 주행 가능 거리(Pleos `Odometer.getRangeRemainingDistance`, 에뮬레이터 0.0), 데모 시작 잔량 저장(지금은 앱을 다시 켜면 처음부터), 화면에서 공급원 바꾸기

## 운행 기록 (2026-11-04)

- 운행: 기어가 P에서 벗어나면 시작, P로 돌아오면 끝(시동 상태는 서드파티에 없다). 움직인 거리 100m 미만이면 남기지 않는다. 앱을 주행 중에 켜면 첫 기어 값에서 시작한다
- 운행에 담는 것(`core/model/Trip.kt`): 시작 시각(벽시계 포함), 거리(속도 적분이라 위치 출처와 무관), 움직인·정차 시간, 최고 속도, 에너지 사용·충전(계량기 차이, 공급원이 바뀐 순간은 뺌), 운전 사건. 위치는 담지 않는다
- 운전 사건(`core/detect/DriveDetector.kt`, 기준은 [pivot-fuel.md](pivot-fuel.md) 13-3): 1초 창 가속도로 급가속(초당 11km/h↑), 급감속(7.5↑), 급제동(브레이크 + 11↑), 긴 정차(P 아닌 채 2분↑). 시작·끝 속도가 모두 20km/h 미만이면 세지 않는다. 사건마다 시작·끝 속도와 최대 가속도를 남겨 습관 비용 계산에 쓴다
- 예전 급정거 판정(`HardBrakeRule`, Road Sensor 때 3.5m/s² 0.5초 유지 기준)은 지우고 위 판정기 하나로 합쳤다
- 저장: 끝난 운행을 앱 전용 저장소 `files/trips.json`(최대 200개)에 쓰고, 서비스 시작 때 되돌린다. 깨진 파일은 `.bad`로 옮기고 빈 기록으로 시작한다
- 에뮬레이터 확인: P만 바꾼 운행은 남지 않음. D → 0→100km/h → BRAKE → P: 123m, 11초, 0.075kWh, 급가속 1·급제동 1로 저장되고, 앱을 다시 켜도 그대로 불러옴. 에뮬레이터 BRAKE는 최대 감속이 약 13.6m/s²(1.4g)로 실차보다 훨씬 세다
- 아직 안 한 것: 진행 중인 운행은 앱이 꺼지면 사라진다. 긴 정차 2분은 정한 값이라 조정할 수 있다. 과속은 제한속도 데이터가 없어 판정하지 않는다

## 운전 습관 비용 (2026-11-04)

- 계산(`core/cost/HabitCost.kt`, 근거 [pivot-fuel.md](pivot-fuel.md) 13-3): 운행의 사건·누적값 × 차 가정값(`VehicleParams.assumedFor`, 데모 소비와 같은 값) × 단가
  - 급제동·급감속: ½·m·(v₁² − v₂²) − 감속 동안 구름·공기저항 몫(감속 시간은 최대 감속도로 잡음) → 전기차는 회생 60%를 뺌 → ÷ 구동 효율. 내연기관 60→0 한 번 약 50원, 전기차 약 10원
  - 고속: 운행이 시속 100km 초과 구간의 Σ(v² − v₀²)·Δs를 쌓고(`Trip.highSpeedExcess`, 저장 파일에도 추가) × ½·ρ·CdA ÷ 효율
  - 긴 정차: 2분 넘는 정차 시간 전체 × 공회전 0.8L/h(내연기관) 또는 보조 0.6kW(전기, 공조 제외)
  - 급가속: 원화 근거가 약해서 횟수만
- 단가: 유가·전기 단가 단계 전까지 가정 단가(`UnitPrices.ASSUMED`: 휘발유 1,700원/L, 전기 347.2원/kWh). 전기 값은 공공 급속 요금 수준으로 잡은 값이라 확인 필요. 화면에 "가정 단가"라고 쓴다
- 평소 대비(`HabitBaseline`): 같은 에너지 종류의 지난 28일 운행 100km당 비용(거리 가중)과 비교해 "평소보다 약 N원 더/덜". 기록이 14일·50km 넘게 쌓이기 전, 1km 미만 운행은 보여 주지 않는다
- 문구(`ui/HabitText.kt`): 금액은 "약"을 붙여 10원 단위로 반올림, 10원 미만은 "10원 미만". 요약 한 줄 + 계산 방법(항목별 금액·양, 쓴 가정값, "추정값이다")
- 에뮬레이터 확인: 0 → 149km/h → 105km/h 감속 → BRAKE → P(0.5km, 21초): 운행 소비 0.35kWh, 습관 비용 약 50원(급제동 0.120kWh 약 40원 + 고속 0.028kWh 약 10원). 손 계산(급제동 약 0.113kWh, 고속 약 0.026kWh)과 맞는다. 주행 중 "지금 운행" 표시는 화면 읽기가 갱신 중에 실패해서 캡처하지 못했다(같은 함수)
- 아직 안 한 것: 시연 영상에서 "평소 대비"를 보이려면 2주치 기록이 필요하다 → 데모 기록을 넣을지 정해야 한다. 공조(전기차 히터·에어컨) 비용은 넣지 않았다

## 단가 (2026-11-04)

- 휘발유: 오피넷 "주유소 전국 평균가격(현재)"(`https://www.opinet.co.kr/api/avgAllPrice.do?out=xml&certkey=<키>`, 문서 apiId=4). 공공데이터포털 15150932는 이 API로 가는 링크(LINK 유형)라 **키는 오피넷에서 따로 받는다**. 응답 `RESULT/OIL`의 `TRADE_DT`·`PRODCD`(B027 휘발유, B034 고급휘발유, D047 경유, K015 자동차용부탄)·`PRICE`(원/L)를 읽는다. JSON 예시가 문서에 없어서 XML을 쓴다(외부 엔티티·DTD 막음)
  - 수집 서비스가 캐시(앱 전용 저장소) → 12시간 넘었으면 다시 받기, 실패하면 15분 뒤 재시도, 1시간마다 확인. 위치를 보내지 않고 로그에 키를 남기지 않는다
  - 키는 저장소 밖 `~/.android-keys/fuel-mate/api-keys.properties`(`opinetCertKey`)에서 빌드 때 `BuildConfig`로 들어간다. APK에서 꺼낼 수 있다. 없으면 가정 단가 1,700원/L
  - 키 없이 부르면 HTTP 200에 빈 `<RESULT>`가 온다(2026-11-04 확인) → 해석 실패로 처리
  - 키를 넣고 에뮬레이터에서 확인(2026-11-04): 휘발유 1,855.29원/L, 경유 1,841.83, 자동차용부탄 1,177.22(기준일 20261104). 다시 켜면 캐시를 쓰고 다시 요청하지 않았다. 로그에 키가 남지 않는다
  - 경유·LPG 차는 아직 휘발유 값·발열량으로 계산한다(경유·부탄 값은 이미 받는다)
- 전기: 기후에너지환경부 공공 충전요금 5단계(2026-08-01 시행, 7-01 확정 발표): 30kW 미만 295.0, 30~50kW 307.2, 50~100kW 325.6, 100~200kW 348.4, 200kW 이상 393.1원/kWh. 공공 충전기와 협약 민간 충전기의 기후부 회원카드 결제에 적용, 민간 자체 요금은 다르다. 값은 보도 기준이라 공식 고시 원문 확인 필요. 사용자가 단계를 고르고(기본 100~200kW, `--es chargeTier`) 앱을 다시 켜도 유지
- 습관 비용 계산과 화면은 이제 이 단가와 근거("오피넷 전국 평균 휘발유(날짜)" 또는 "가정 단가")를 쓴다
- 오피넷·충전요금 출처와 이용 조건은 README에 남겼다. 공공데이터포털은 "이용허락범위 제한 없음", 오피넷 저작권정책은 수익 목적이면 사전 협의

## 주유소 추천 (2026-11-05)

- 흐름: 지금 위치 → 오피넷 반경 검색(지금 위치 + 진행 방향 5km 앞, 반경 5km씩, 휘발유 가격순) → 후보마다 실제 이득 → 1등 추천 → "경유지 추가"(`--es waypoint best`, 화면 버튼은 다음 단계)
- KATEC 변환(`core/geo/Katec.kt`): 라이브러리 없이 직접 구현(WGS84 ↔ 지구중심 좌표 ↔ 7변수 변환 ↔ Bessel ↔ 횡메르카토르). 정의는 `+proj=tmerc +lat_0=38 +lon_0=128 +k=0.9999 +x_0=400000 +y_0=600000 +ellps=bessel +towgs84=-115.80,474.99,674.11,1.16,-2.31,-1.63,6.43`. 오피넷 문서 예시 좌표를 풀면 서울 역삼동이 나와 오피넷과 맞고, PROJ 9.3(pyproj, 저장소 밖 작업 폴더에서만 씀)으로 만든 기준값 5곳과 0.1m 안에서 맞는다. 문서 예시 응답의 주유소 거리도 응답 `DISTANCE`와 3m 안에서 맞는다
- 반경 검색(`core/station/Station.kt`): `aroundAll.do?out=xml&x&y&radius(≤5000)&sort=1&prodcd=B027`. 상표 태그는 문서 표(`POLL_DIV_CD`)와 예시(`POLL_DIV_CO`)가 달라 둘 다 읽는다. 오피넷에는 검색 중심 좌표만 보내고 로그에 좌표·키를 남기지 않는다
- 실제 이득(`StationRecommender`): 비교 기준 = 우회가 가장 적은 주유소("그냥 가까운 데서 넣었다면"). 이득 = (기준 가격 − 후보 가격) × 넣을 양 − (후보 우회 − 기준 우회) × 0.09L/km(약 11km/L 가정) × 기준 가격. 넣을 양은 가득(용량 − 잔량). 우회 = (지금→주유소→앞쪽 지점 − 지금→앞쪽 지점) × 1.3(도로 보정), 6km 넘으면 제외. 이득이 300원 아래면 가까운 곳을 추천
- 언제 찾나(`StationSearchRule`): 연료 50% 이하일 때, 처음이거나 3km 움직였거나 15분 지났으면. 한 번에 2건이라 하루 1,500건 한도를 아낀다. 실패하면 5분 뒤
- 내비(`app/navi/NaviWaypoint.kt`): 안내 중이면 `addWaypoint(FIRST)` → `onWaypointChanged(ADD)`의 `routeStartInfo.distance` − 넣기 전 목적지 거리(`onDrivingInfo`) = 실제 우회. 안내 중이 아니면 주유소로 `requestRoute`(우회 거리 없음). POI ID 없이 좌표·이름만 넣는다. 권한 `NAVI_ROUTE_SEARCH` 추가
- 에뮬레이터 확인(데모 경로 시흥동 근처, 연료 25%): 실제 오피넷 응답으로 35곳(지금 위치 27, 앞쪽 33, 겹침 제외) → "한강에너지(주) 1,833원 · 우회 약 3.7km · 가까운 곳보다 약 1,680원 이득"(기준 SK에너지 스타팅광동주유소 1,884원, 가득 45L). `--es waypoint best` → 안내 중이 아니라 주유소로 경로 요청, 내비 앱이 음성 안내를 시작했다
- 아직 안 한 것: 안내 중 경로에 경유지를 넣어 실제 우회 거리 받기(내비에 목적지가 있어야 함), 충전소 추천, 경유·LPG 가격 선택, 하루 호출 한도를 넘는 규모는 서버 캐시나 석유공사 협의가 필요(pivot-fuel 5장)

## 화면 (2026-11-05)

- 네이티브 Android View(코드로 구성, XML 없음)로 만들었다(사용자 결정). 남은 기간과 글자·버튼 위주 화면이라는 이유. 웹 강점은 나중에 정차 화면의 그래프 같은 곳에 WebView로 넣을 수 있다
- 구조: 상태 → `ui/ScreenModel`(문구만 뽑은 값, 같으면 다시 그리지 않음) → `DrivingScreen` / `ParkedScreen`. 주행/정차는 `state.drive.restricted`(CarUxRestrictions)만 따른다. 개발용 상태 글자는 `--es screen status`(되돌리기 `--es screen app`)
- 정차 화면: 연료 줄, 추천 카드(이름·가격·우회, 초록 큰 글씨 "가까운 곳보다 약 N원 이득", 가득 기준·비교 대상, [경유지 추가], 다른 곳 2곳과 각 [경유지], 내비 상태), 지난/지금 운행 카드(습관 비용 요약, 거리·시간·사용량, [계산 방법 보기] 펼침), 단가 근거. 가로가 넓으면 두 열, 아니면 한 열
- 주행 화면: 큰 글자 한 줄(48sp) + 보조 한 줄(30sp) + [경유지 추가] 하나(높이 120dp). `LIMIT_CONTENT`면 보조 줄을 숨기고, `LIMIT_STRING_LENGTH`면 이름을 12자에서 자른다. 목록·펼침·설정·애니메이션 없음
- 기준(docs/pleos/ui-design-guide.md): 대비를 WCAG 식으로 계산해 모두 4.5:1 이상(가장 낮은 곳 주간 이득 글자 5.0:1). 주요 글자 36sp 이상(에뮬레이터 160dpi에서 약 5.7mm), 보조 20sp(약 3.2mm). 주간·야간은 시스템 야간 모드를 따른다. 법인 표기("(주)" 등)를 빼서 이름을 짧게
- 에뮬레이터 확인: 정차 화면(주간 모드) 캡처, D로 바꾸자 주행 화면으로 바뀜, 주행 화면 [경유지 추가] → 안내 중 경로에 한강에너지가 경유지로 들어가고 내비가 4,800m 경로로 다시 안내
- 내비 연동에서 새로 안 것: `isRouting`은 안내 중에도 false라 `naviMode`로 판단, 넣기 전 남은 거리 값이 이상함(docs/pleos/navihelper-sdk.md "에뮬레이터에서 확인한 것"). 안내가 끝나면(도착·안내 없음) "경유 중" 표시를 지운다
- 경유지를 고른 뒤 정차 카드(2026-11-05): 카드가 고른 주유소 기준으로 바뀐다. 제목 "경유 중인 주유소"(목적지로 안내면 "안내 중인 주유소"), 가격·추정 우회, "가까운 곳보다 약 N원 이득"(손해면 "더 들어요"), 추천과 다르면 "추천 ○○보다 약 M원 덜 아껴요". 큰 [경유지 추가]는 숨기고 추천은 "다른 곳"에 "추천"을 붙여 내린다. 비교는 `Recommendation.chosen`(`:core`, 모든 후보에서 찾음, 화면 목록은 5곳)으로 계산하고 `:core` 테스트 67개. 고른 곳이 다시 찾은 뒤 후보에서 빠지면 이름과 내비 줄만 보인다. 카드 본문 우회는 추정값만 쓴다(내비 실제 우회가 넣기 전·후 4,600 → 4,600m처럼 같게 와서 0.0km로 나오는 일이 있음, 내비 줄에만 보임)
  - 에뮬레이터 확인(두 번째 맥): 분당로주유소 → "약 1,510원 이득 · 추천 한강에너지보다 약 170원 덜", 서현주유소 → "약 940원 이득 · 약 740원 덜"
  - 알아 둘 것: 경유지 상태는 메모리에만 있어서 앱을 다시 켜면 추천 카드로 돌아간다(내비는 그대로 안내 중). "다른 곳"의 [경유지]를 또 누르면 내비에 경유지가 하나 더 붙는다

## 내비 목적지 기준 추천 (2026-11-06)

- 사용자 결정: 앱을 켜면 데모 추천이 바로 뜨는 대신, 운전자가 내비에 넣은 목적지 기준으로 추천한다. 위치 기본값을 `NAVI`로 바꿨다. 데모 궤적은 `--es location DEMO`로 남겼다
- 목적지가 없으면 검색·추천하지 않고 "내비에 목적지를 넣으면 가는 길 주유소를 찾아요"라고 안내한다(`StationSearchRule`, `StationRecommender.recommend`). 호출도 아낀다. 목적지가 500m 넘게 바뀌면 바로 다시 찾는다(`StationSearch.destination`)
- 앞쪽 지점은 목적지 쪽 직선 5km다. NaviHelper에 경로 선형 API가 없어 실제 도로를 따라가지 않는다. 진행 방향(heading) 기준은 뺐다
- 에뮬레이터 내비 위치는 고정이라 `core/geo/StuckNaviFallback`을 넣었다: 내비 위치가 멈춘 채 차가 200m 넘게 달리면 차량 속도로 목적지 쪽 직선을 따라 움직인다(`LocationOrigin.NAVI_SIMULATED`, 화면에 "위치 데모(직선 이동)"). 내비 위치가 한 번이라도 움직이면 실차로 보고 다시는 흉내 내지 않는다. `:core` 테스트 76개
- 에뮬레이터 확인(두 번째 맥): 목적지 없음 → 안내 문구, 검색 없음. 내비에서 강남파이낸스센터(14km) 안내 시작 → 약 11초 안에 48곳 찾음(지금 위치 27, 앞쪽 25) → 추천 한강에너지 약 2,590원 이득, 비교 청계산주유소 1,904원. [경유지 추가] → "경유 중인 주유소", 재검색 없음(경유지를 넣는 동안 목적지가 잠깐 없어졌다가 돌아온다). 안내 종료 → 안내 문구로 돌아감, 검색 없음
- 주행 확인(Virtual Console D + ACCEL, 강남파이낸스센터로 안내 중): 출발 약 10초 뒤 위치 출처가 `NAVI_SIMULATED`로 바뀌고, 주행 화면은 큰 글자 한 줄 + 보조 한 줄 + [경유지 추가]. 움직이면서 이득·우회 값이 바뀐다(약 2,590원·3.8km → 약 2,500원·4.4km → 약 850원·4.8km). 1.7km 달리고 P로 바꾸니 운행이 저장되고 정차 화면에 "위치 데모(직선 이동)"가 보이고 추천이 대신석유대우주유소로 바뀌었다
- 목적지 변경 확인: 안내 중 목적지를 판교테크노밸리로 바꾸자 경로 시작 약 6초 뒤 다시 찾았다(36곳, 비교 기준 판교서일주유소). 3km 움직였을 때 재검색은 단위 테스트로만 확인했다(에뮬레이터 주행이 1.7km에서 끝남)
- 실제 우회 바로잡음: `WaypointChangedInfo.routeStartInfo.distance`는 경유지까지 거리였다(2,300m 경로에 넣자 4,800m, 목적지는 9,200m). 앱이 이 값을 목적지 거리로 착각해 우회를 2,500m로 틀리게 냈다. 이제 넣은 뒤 목적지 거리(`onDrivingInfo`·`remainDistance`)로 구한다(`NaviWaypoint`, docs/pleos/navihelper-sdk.md). 에뮬레이터 확인: 2,300 → 9,200m, 실제 우회 6.9km
- 실제 우회가 오면 고른 곳의 이득을 그 값으로 다시 계산한다(`Recommendation.chosen(id, actualDetourM)`, `:core` 테스트 77개). 확인: 한강에너지가 추정 우회 약 4.6km·약 2,280원 → 실제 우회 6.9km·약 1,880원. 추천 순위는 여전히 추정 우회로 정한다(내비에 넣기 전에는 실제 값을 모른다)
- 알아 둘 것: 직선 × 1.3 추정이 실제 도로보다 꽤 작을 수 있다(4.6km ↔ 6.9km 한 건). 넣기 전 금액은 "약"이고, 넣은 뒤 실제 값으로 바뀐다. 표본이 더 쌓이면 도로 보정(1.3)을 다시 본다
- 기획서의 숫자(약 1,680원)는 판교역 방향 값이다. 캡처를 다시 찍을 때 목적지를 판교역으로 넣고 숫자가 맞는지 확인한다
- 맥 DNS 문제로 에뮬레이터가 이름을 못 찾으면 "주유소를 찾는 중"에서 멈춘다. 그때는 `-dns-server 8.8.8.8,1.1.1.1`을 붙여 켠다

## 첫 화면 (2026-11-06)

- 사용자 결정: 목적지가 없을 때는 앱이 하는 일을 알려 주고 도착지부터 받는다. 내비 SDK에 장소 이름 검색 API가 없어 앱 안 입력창 대신 A안으로 갔다(외부 검색 API는 키 발급과 입력한 목적지의 외부 전송이 필요해 뺐다)
- 화면(`StartCard`, 정차 중 목적지·경유지가 없을 때): 소개 문구, [어디로 가세요?](내비 앱 열기, `CATEGORY_APP_MAPS`), "바로 가기"(집·회사·즐겨찾기·최근 순 4곳, 같은 곳은 하나만, `SavedPlaces`, `:core` 테스트 80개) + [안내](`requestRoute`). 전기차는 충전소 준비 중 안내를 그대로 보인다
- 저장된 곳은 내비가 가진 값을 메모리에만 두고 로그에 이름·좌표를 남기지 않는다(`NaviPlaces`)
- 에뮬레이터 확인: 첫 화면, 최근 목적지 3곳, [안내] → 14km 경로 시작, 목적지 인식. 안내 종료 → 첫 화면으로 돌아옴. [어디로 가세요?] → 내비 검색 → 안내 시작 → 작업 표시줄 아이콘으로 복귀 → 추천 카드(화면 캡처로 확인)
- 고친 것: [어디로 가세요?]가 처음에는 "내비게이션을 실행 중입니다"에서 멈췄다. 선택자 인텐트가 내비를 새 태스크로 하나 더 띄운 탓이다. 작업 표시줄과 같은 실행 인텐트로 바꿨다(docs/pleos/navihelper-sdk.md). 부팅 직후·반복·내비 강제 종료 뒤 모두 확인
- 안 되는 것: 안내가 시작돼도 앱이 스스로 앞으로 나올 수 없다(`Background activity launch blocked`). 시험한 코드는 지웠고, 화면에 "안내가 시작된 뒤 이 앱을 다시 열면 추천이 보여요"라고 쓴다
- 알아 둘 것: 최근 목적지에 경유지로 넣은 주유소도 들어온다(시험 때 한강에너지(주)). 즐겨찾기 2곳은 왔지만 이름 또는 좌표가 비어 목록에 안 나왔다(에뮬레이터 기본값으로 보임, 값은 미확인)

## 정차 화면 가독성 (2026-11-06)

- UI Design Guide의 "1~2초 안에 파악"에 맞춰 고쳤다. 첫 화면: 제목 + 설명 한 줄 + [어디로 가세요?], 바로 가기는 이름을 먼저 크게(26sp). 추천 카드: 이득 금액을 맨 위에 가장 크게, 이름·가격·우회 한 줄, 비교 기준 작게. 다른 곳은 가격·우회·이득 열을 맞춘 표. 내비 줄은 상태만 말한다(이름·우회는 위에 있음)
- 작은 글씨를 20sp에서 22sp로 올렸다(약 3.5mm). 색과 대비는 그대로다. 주행 화면은 바꾸지 않았다
- 넓은 화면 배치: 카드를 화면 높이까지 늘려 아래쪽 빈 공간을 없앴다. 왼쪽(1.5) 첫 화면·추천 카드, 오른쪽(1) 연료 카드(%·게이지·양·단가)와 운행 카드. 위쪽 연료 줄은 연료 카드로 옮겼다. 다른 곳 표는 4곳까지, 금액 64sp(약 10mm), 줄 글씨 26~30sp. 넓은 화면은 계산 방법을 처음부터 펼친다. 운행 기록이 없으면 운행 카드에 무엇을 보여 줄지 안내한다
- 에뮬레이터 캡처 확인: 추천 카드, 첫 화면(배치를 바꾸기 전 글씨 크기로는 경유 중 카드도 확인). 야간 모드와 좁은 화면(분할·세로), 운행 기록이 없을 때는 아직 안 봤다

## 첫 화면 애니메이션 (2026-11-07)

- 사용자 결정: [어디로 가세요?]와 그 아래 안내 문구를 맨 아래로 내리고, 맨 위에 애니메이션을 넣는다. 순서는 그림(남는 높이 전부, 최소 240dp) → 소개 문구 → 바로 가기 → 버튼 → 안내 문구다
- 내용(`ui/RouteGainView`, 라이브러리 없이 Canvas): 경로가 그려지고 주유소 핀 3곳이 나온 뒤, 내비 화살표가 앞의 두 곳을 지나 세 번째 핀에 닿으면 핀이 초록색으로 바뀌고 "이득" 표시가 붙는다. 목적지를 넣기 전이라 금액은 넣지 않는다
- 재생 규칙: 화면에 보일 때 3.6초 동안 한 번 재생하고 마지막 장면에서 멈춘다. 반복하지 않는다. 뷰가 안 보이게 되면(주행 화면 전환, 내비가 앞으로 나옴) 바로 멈추고, 다시 보이면 처음부터 한 번 재생한다. UI Design Guide가 금지한 "운전 중 시선을 빼앗는 애니메이션"을 피하려고 정차 중 첫 화면에만 둔다. 주행 화면은 바꾸지 않았다
- 에뮬레이터 캡처 확인: 재생 중 장면과 마지막 장면(주간·야간), 멈춘 뒤 8초 동안 그림 영역 변화 없음, [어디로 가세요?] → 내비 열림 → 앱으로 돌아오면 다시 재생
- 아직 안 본 것: 주행 전환 때 멈추는지(Virtual Console 주행은 사용자), 좁은 화면(분할·세로), 바로 가기 4곳일 때, 추천 카드로 넘어갈 때

## 추천 카드 금액 연출 (2026-11-07)

- 사용자 결정: 추천 카드도 [경유지 추가]를 맨 아래로 내리고, 이득 금액이 잘 보이게 첫 화면처럼 애니메이션을 넣는다. 순서는 금액 → 이름·가격·우회 → 비교 기준 → 그림(남는 높이, 최소 180dp) → 다른 곳 표 → 버튼이다
- 금액: 글자를 76sp로 키웠다. 그림과 같은 시계로 10원부터 실제 금액까지 올라가고, 차가 도착할 때 한 번 8% 커졌다가 돌아온다. 그림의 초록 핀에 실제 금액("약 2,590원 이득")이 붙는다. 그림은 실제 지도가 아니라 설명 그림이다(앞의 두 핀은 실제 후보 위치가 아니다)
- 재생 규칙: 첫 화면과 같고 2.6초로 더 짧다(1~2초 안에 파악). 이득이 없는 카드("가까운 곳에서 넣어도 차이가 작아요", 더 드는 경우, 안내 문구)는 그림과 올라가는 연출 없이 글자만 보인다. 추천 주유소가 바뀌면 다시 재생하고, 금액만 바뀌면 다시 재생하지 않는다. 주행 화면은 바꾸지 않았다
- 에뮬레이터 캡처 확인: 재생 중 장면과 마지막 장면(주간), 앱을 새로 켜서 "주유소를 찾는 중" → 추천 카드로 바뀔 때 재생, 내비에서 돌아올 때 재생
- 아직 안 본 것: 경유지를 넣은 뒤 카드(버튼이 숨고 내비 상태 줄이 맨 아래), 야간 모드의 추천 카드, 이득이 없는 카드, 주행 전환 때 멈추는지, 좁은 화면
- 알아 둘 것: 앱을 새로 켜면 금액이 나오기까지 약 13초 걸린다(2026-11-07 한 번 측정, 이번 변경 전 코드에도 있던 흐름으로 보임, 원인은 미확인). 그동안 카드에는 "주유소를 찾는 중"만 보인다

## 안내 종료 뒤 첫 화면으로 (2026-11-08)

- 문제(사용자 캡처): 경유지를 넣는 중에 내비 안내를 끝내면 카드가 "경유 중인 주유소 · 내비에 경유지를 넣는 중이에요"에 멈추고 첫 화면으로 돌아가지 않았다. 넣는 중에는 내비가 잠깐 안내 없음이 되므로 앱이 이를 "안내 끝"으로 보지 않는데, 넣기 응답이 끝내 오지 않으면 그 상태가 풀리지 않았다
- 고친 것(`NaviWaypoint`): 넣기 응답을 15초 기다린 뒤 포기하고 넣기 전 상태로 되돌린다. 그때 안내가 끝나 있으면 경유 상태를 지워 첫 화면으로 돌아간다. 실제 우회 거리를 기다리는 시간도 30초에서 15초로 줄였다
- 에뮬레이터 확인: 다른 곳 [경유지] → 내비 미리보기에서 [X] → 앱이 "넣는 중"으로 15초 뒤 첫 화면으로 돌아옴(로그 "경유지 추가 응답 없음", "안내가 끝나 경유 상태를 지움"). 경유지가 들어간 정상 흐름도 다시 확인했다
- 남은 것: 넣는 중에 끝내면 첫 화면까지 최대 약 20초 걸린다(15초 + 상태 확인 5초 간격)
- 경유지 바꾸기(같은 날): 경유지를 넣은 뒤 다른 곳 [경유지]를 또 누르면 내비에 경유지가 쌓이고 실제 우회도 두 번째 몫만 잡혔다(9.7km → 27km를 "우회 17.3km"로 셈). 이제 경유지가 들어간 뒤에는 다른 곳 버튼이 [바꾸기]가 되고, 앞의 경유지를 뺀 뒤(`removeWaypoint(FIRST)`) 뺀 거리를 "넣기 전"으로 새 곳을 넣는다. 넣거나 바꾸는 중에 온 요청과 이미 경유 중인 곳은 넘긴다. 빼기 응답이 15초 안에 없으면 앞의 경유지가 그대로라고 보고 되돌린다
- 에뮬레이터 확인: 한강에너지 경유(실제 우회 5.0km) → 에너지 플러스 허브 내곡으로 [바꾸기] → 내비 "경유지 1개 포함", 실제 우회 3.0km(13,000 → 16,000m), 카드 약 1,110원 이득, 표에 "추천 한강에너지"가 돌아옴. 바꾸는 동안 내비가 두 번 앞으로 나오고 약 15초 걸린다
- 안 본 것: 바꾸는 중에 안내를 끝냈을 때, 넣는 중 두 번 누르기(첫 탭에 내비가 앞으로 나와 화면에서는 누르기 어렵다), 사용자가 내비에서 직접 넣은 경유지가 있을 때(우리 것이 FIRST라고 보고 뺀다)
